# OnlineLecture 강의 플랫폼 MVP 설계

## 목표와 운영 범위

OnlineLecture는 넓은 여백과 절제된 에디토리얼 분위기의 비상업 온라인 강의 MVP다. OCMD는 분위기만 참고하고 브랜드, 문구, 이미지와 레이아웃을 복제하지 않는다. Google 로그인 회원에게 여러 강의와 회차별 공개 YouTube 영상을 제공하고, 공개 게시판 열람과 회원의 글·댓글·검색·문서 첨부를 지원한다. 운영자는 강의, 회차, 공지, 게시물, 댓글과 저장공간을 관리한다.

초기 목표는 6개월간 사용자 100~300명, 동시 공개 읽기 요청 20~30명이다. Vercel Hobby와 Supabase 무료 플랜에 공개 배포하고 초기에는 비상업적으로 운영한다.

## 외부 준비와 운영 체크포인트

구현 중 다음 순서로 외부 계정을 준비한다.

1. Supabase 개발 프로젝트 하나를 생성한다.
2. YouTube 채널과 공개 테스트 영상을 준비한다.
3. Resend 계정을 만들고 계정 소유자 이메일만 용량 경고 수신자로 둔다.
4. GitHub 저장소와 Vercel 프로젝트를 연결한다.
5. P09 배포 인수 직전에 Google Cloud OAuth 앱을 만들고 기본 신원 범위와 Supabase·Vercel 리디렉션 URL을 등록한다.

P03 인증 구현과 자동 검증은 로컬·모의 OAuth 경계로 진행하며 실제 Google 계정 설정은 요구하지 않는다. 실제 Google 로그인은 배포 URL이 확정된 P09에서 한 번만 설정하고 수동 검증한다.

첫 Google 로그인 후 해당 사용자를 한 번의 버전 관리 SQL migration 또는 관리 쿼리로 `admin`으로 승격한다. 관리자 역할 편집 UI는 만들지 않는다.

저장소 범위 Codex MCP 설정을 우선한다. shadcn MCP는 공식 레지스트리만 사용한다. Supabase MCP는 개발 프로젝트 하나에 `read_only=true`로 연결하고 DB 변경에는 사용하지 않는다. Playwright MCP는 공식 `@playwright/mcp`를 격리·헤드리스 모드로 사용한다. GitHub MCP, Context7과 추가 브라우저 MCP는 제외한다. 저장소 범위 설정이 지원되지 않을 때만 사용자 승인 후 전역 설정을 사용한다.

## 기술 구조

- Next.js App Router와 TypeScript로 UI와 서버 로직을 한 저장소에서 관리한다.
- Supabase Auth, PostgreSQL, Storage로 Google 인증, 관계형 데이터, 비공개 문서 저장과 RLS를 제공한다.
- Vercel Hobby에 배포하며 상업화 전에 Pro 전환을 검토한다.
- Tiptap 오픈소스 코어만 사용하고 Pro 및 커뮤니티 확장은 제외한다.
- Resend는 저장공간 80% 도달 경고 이메일 한 종류에만 사용한다.
- Zod 스키마로 서버 입력, URL, 검색 파라미터와 파일 메타데이터를 검증한다.
- Vitest는 순수 로직, Playwright는 실제 브라우저 사용자 흐름을 검증한다.
- Supabase CLI 로컬 설정과 CLI 생성물 제외 규칙을 두고 Docker 기반 PostgreSQL 스택으로 migration 및 pgTAP 검사를 재현한다.
- ORM, 전역 상태관리, React Hook Form, 별도 검색 엔진과 CMS는 추가하지 않는다.

서비스 역할 키와 Resend 키는 서버에서만 사용한다. 실제 비밀 값은 로컬과 Vercel 환경 변수에 저장하고 `.env.example`에는 변수명과 설명만 둔다.

## 디자인 시스템

shadcn/ui `Sera` 스타일, Base UI와 Tailwind CSS v4를 기반으로 한다. 필요한 공식 컴포넌트만 설치한다: Button, Input, Textarea, Label, Dialog, Dropdown Menu, Select, Tabs, Badge, Table, Pagination, Alert, Progress, Skeleton, Sonner.

프로젝트 기반 단계에서 Tailwind CSS v4의 PostCSS 플러그인과 전역 CSS 진입점을 연결하고, Next.js 타입 선언과 생성물 제외 규칙을 함께 둔다.

Noto Serif KR는 제목, Noto Sans KR는 본문과 컨트롤에 `next/font` 자체 호스팅으로 적용한다. 토큰은 다음과 같다.

- 배경 `#F7F7F2`
- 표면 `#FFFFFF`
- 본문 `#171717`
- 보조문구 `#6B6B65`
- 경계 `#D9D9D2`
- 강조 `#C8FF3D`
- 위험 `#C93C37`
- 성공 `#18794E`

콘텐츠 최대 폭은 1200px, 읽기 본문은 760px, 좌우 여백은 모바일 20px·데스크톱 32px이며 4px 간격 체계를 사용한다. 모서리는 2px 중심으로 유지한다. 과한 그림자, 그라데이션과 카드 중첩은 금지하고 다크 모드는 제외한다. 모든 컨트롤은 키보드 조작, 보이는 포커스, 44px 터치 영역과 WCAG AA 수준 대비를 갖춘다.

선택한 패키지의 MIT, Apache-2.0, ISC, OFL 라이선스와 정확한 설치 버전을 README에 기록하고 원문 고지를 보존한다. 기능 단계에서 패키지를 추가하는 통합 작업자가 같은 논리 단위에서 README 기록도 함께 소유한다.

## 페이지와 권한

인증 클라이언트는 `@supabase/ssr`와 `@supabase/supabase-js`의 PKCE·쿠키 기반 브라우저/서버 경계를 사용한다. Next.js 16의 요청 경계는 `src/proxy.ts`로 구현하며, 여기서는 세션 쿠키 갱신만 담당한다. 보호 경로와 역할 판정은 후속 서버 경계에서도 다시 검증하고 브라우저에 service role 키를 노출하지 않는다.

- 공개: 홈, 로그인, 게시판 목록·본문·검색
- 회원: 별명 설정, 강의 목록·상세·회차 재생·자료 다운로드, 글·댓글 작성과 자신의 콘텐츠 수정·삭제
- 운영자: 강의·회차 CRUD와 순서 변경, 자료 업로드, 공지 고정, 전체 콘텐츠 삭제, 저장량 확인

온보딩 페이지는 서버에서 인증 사용자를 확인한 뒤에만 클라이언트 별명 폼을 렌더링하며, 비인증 접근은 안전한 내부 로그인 경로로 보낸다.

홈은 짧은 소개, 강의 미리보기, 최근 공지·게시글과 로그인 CTA로 구성한다. 강의 경로는 로그인으로 보호한다. YouTube 영상 자체는 공개이며 플랫폼 인증만으로 영상 접근을 완전히 보호할 수 없다는 한계를 운영 문서에 명시한다.

## 데이터 모델

- `profiles`: Auth 사용자 ID, 공개 별명, `member|admin` 역할
- `courses`: 제목, slug, 소개, 공개 상태
- `lessons`: 강의 ID, 순서, 제목, 설명, YouTube 영상 ID
- `posts`: 작성자, 선택적 강의 태그, 제목, Tiptap JSON, 검색용 일반 텍스트, 공지 여부
- `comments`: 게시글, 작성자, 일반 텍스트 본문
- `attachments`: 게시글 또는 회차, Storage 경로, 원래 파일명, MIME, 크기
- `storage_settings`: 무료 한도, 현재 경고 단계, 마지막 이메일 발송 상태

RLS가 비회원 읽기, 회원 작성, 작성자 수정·삭제, 운영자 전체 관리 권한을 데이터베이스 수준에서 강제한다. 미공개 강의와 관련 회차 및 첨부는 운영자만 읽을 수 있다. 검색과 정렬에 필요한 인덱스, 별명 대소문자 무관 유일성, 회차 순서 무결성은 migration에서 정의한다.

## 입력과 콘텐츠 동작

별명은 2~20자의 한글, 영문, 숫자, 밑줄만 허용하고 대소문자를 무시해 중복을 차단한다. 이 형식은 서버 검증과 PostgreSQL CHECK 제약에서 함께 강제해 브라우저의 직접 REST 호출로 우회할 수 없게 한다. 게시글 제목은 1~120자, Tiptap JSON에서 환산한 일반 텍스트 본문은 1~20,000자다. 댓글은 일반 텍스트 1~2,000자다.

리치 텍스트는 제목, 굵게, 기울임, 취소선, 목록, 인용, 링크, 실행취소만 제공한다. Tiptap JSON만 저장하고 허용 노드로 렌더링하며 임의 HTML 입력은 받지 않는다.

게시판 검색은 제목과 검색용 본문의 escaped `ILIKE` 부분 검색이다. 공지 우선·최신순으로 정렬하고 페이지당 20개, 강의 태그 필터를 제공한다. 특수문자가 와일드카드로 해석되지 않게 escape한다.

YouTube 입력은 `youtube.com`과 `youtu.be` URL만 허용하고 추출한 영상 ID만 저장한다. 첫 회차의 YouTube 썸네일을 강의 대표 이미지 기본값으로 사용한다. 회차 순서는 드래그앤드롭 없이 위·아래 이동 버튼으로 관리한다.

## 문서 업로드와 용량 경고

허용 형식은 JPG, PNG, WebP, GIF, PDF, DOC, DOCX, PPT, PPTX, XLS, XLSX, ZIP이다. 실행 파일, HTML, SVG와 허용 목록 밖 형식은 거부한다. 확장자와 MIME을 함께 검사한다. 파일당 최대 10MB이며 게시글당 최대 3개, 회차당 최대 3개다.

Storage 버킷은 비공개로 유지한다. 서버가 데이터 권한을 확인한 뒤 만료형 다운로드 URL을 발급한다. 업로드 전 요청 파일 합계를 포함한 예상 전체 사용량을 검사한다. 무료 한도는 1GB다.

- 사용량이 처음 80%를 넘으면 관리자 화면 경고를 표시하고 Resend 이메일을 한 번 발송한다.
- 95% 이상이 예상되면 모든 신규 업로드를 차단한다.
- 삭제 후 95% 아래로 내려가면 업로드를 다시 허용한다.
- 사용량이 80% 아래로 내려가면 경고 상태를 초기화해 재상승 시 이메일을 다시 보낼 수 있다.
- 객체 업로드 후 DB 기록이 실패하면 객체를 정리한다.
- 객체 삭제가 실패하면 사용자에게 삭제 성공으로 표시하지 않는다.

## 오류와 공통 상태

오류, 404, 권한 없음, 빈 상태와 로딩 UI를 공통 패턴으로 제공한다. 서버 입력 오류는 필드 또는 폼 수준의 한국어 메시지로 반환하고, 인증·권한 오류는 존재 여부를 불필요하게 노출하지 않는다. 사용자에게 재시도 가능한 오류와 운영자 조치가 필요한 오류를 구분한다.

## 구현 단계

1. 문서, 작업 하네스, AI 규칙, 환경 변수 예시와 MCP 설정을 준비한다.
2. Next.js, TypeScript, Tailwind 프로젝트와 디자인 토큰, 공개 레이아웃을 구축한다.
3. Supabase migration으로 테이블, 인덱스, RLS, Storage 정책을 작성하고 생성 타입을 연결한다.
4. Google OAuth, 콜백, 보호 경로, 별명 온보딩과 관리자 승격 절차를 구현한다.
5. 강의 목록, 상세, 회차 플레이어와 관리자 강의·회차 CRUD를 구현한다.
6. Tiptap 게시글 CRUD, 댓글, 검색, 필터, 공지와 운영자 삭제를 구현한다.
7. 게시글·회차 자료 업로드, 다운로드, 용량 경고와 차단을 구현한다.
8. 공통 오류·빈 상태·로딩 UI를 마감한다.
9. 테스트, 접근성, 부하 스모크를 통과시키고 Vercel에 배포한다.
10. 배포 URL에서 외부 연동과 Supabase Advisor를 최종 확인한다.

각 기능 작업은 실패 테스트 작성, 실패 확인, 최소 구현, 통과 확인, 작은 커밋 순으로 진행한다.

## 테스트와 인수 조건

- 단위: 별명, YouTube URL, 파일 MIME·확장자·크기, Tiptap 본문 길이, 검색 파라미터, 용량 임계값
- 인증: OAuth 콜백·쿠키와 온보딩 서버 액션의 인증, 사용자 ID 고정, 별명 중복·일반 오류 경계
- 관리자 승격: 지정 사용자만 1회 승격되고 재승격·임의 대상·브라우저 직접 변경이 거부되는 SQL 경계
- 권한: 비회원·회원·작성자·운영자의 CRUD와 자료 접근을 RLS 수준에서 구분
- 강의: 다중 강의, 회차 순서, 미공개 강의, 잘못된 YouTube URL, 빈 회차
- 강의 화면: 회원 가드, 공개 강의·회차 조회 체인, 첫 회차 썸네일, 빈·오류·notFound 분기를 서버 페이지 테스트로 검증
- 게시판: 검색 특수문자, 강의 필터, 공지 우선, 페이지네이션, 본인·타인 수정/삭제
- 업로드: 3개 초과, 10MB 초과, 위장 MIME, DB 실패 정리, 80% 이메일 1회, 95% 차단, 삭제 후 복구
- 브라우저: 홈→Google 로그인→별명→강의 재생, 글·댓글 작성, 운영자 관리, 모바일 메뉴
- 접근성: 키보드 탐색, 포커스, 라벨, 오류 안내, 색상 대비
- 성능: 워밍업 후 공개 읽기 경로에 30개 동시 요청을 여러 차례 보내 HTTP 오류 0건

완료 시 lint, typecheck, 단위 테스트, Playwright E2E와 production build가 모두 성공해야 한다. Google OAuth 공급자 승인과 실제 이메일 도착은 배포 환경에서 수동 검증한다.

## 명시적 제외와 전환 기준

결제, 무료 수강 신청, 진도율, 수료증, 좋아요, 실시간 알림, 영상 업로드·보호, 악성 문서 바이러스 검사와 다크 모드는 MVP에서 제외한다.

검색이 실제 사용자 규모에서 느려질 때만 PostgreSQL 전문 검색을 추가한다. 저장공간이 80%에 도달하면 불필요한 첨부를 검토하고 지속 사용이 확인되면 Supabase Pro를 검토한다. 상업화 전에는 Vercel Pro, 이용약관·개인정보처리방침, 회원 전용 영상 서비스, 악성 파일 검사와 백업 정책을 별도로 계획한다. 무료 플랜 한도와 shadcn 기본 구성은 배포 직전에 공식 문서로 다시 확인한다.
